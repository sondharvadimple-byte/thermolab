03 / MODELS

Which model checks which technology?

The website and the terminal program use the same Python engine and the same model numbers. Describe a problem and the analyzer chooses the model (and says why), or pick a model and enter its values.

Two helpers sit behind these models and are not selectable: the property calculator (Δh, Δs, Teff, latent heat — also answers “calculate the enthalpy change” questions without a verdict) and the model-required fallback, which answers MODEL REQUIRED for processes with no validated model here (transient conduction, tidal energy) instead of forcing an unrelated model.

04 / UNDERSTAND

How the tester decides

Every verdict comes from deterministic Python calculations. Nothing is guessed: missing values are calculated only when the equations fix them, and every assumption is shown.

01

Read and map the scenario

The analyzer finds every number with its unit and converts it before any calculation (°C → K, W → kW, g/s → kg/s, L/s → m³/s). It reads the surrounding words to give each quantity a role — heat received, heat rejected, work produced or consumed, stream inlet or outlet, reservoir temperature.

From the technology and these roles it chooses the model: a heat engine between fixed temperatures is not a heat exchanger, a refrigerator consumes work, a finite stream is not a fixed-temperature reservoir. The result states which model was chosen and why.

02

Calculate the thermodynamic limit

The engine applies the selected model: the First Law (energy balance) and the Second Law (Sgen ≥ 0). Values that the balances fix uniquely are calculated — a stream outlet, rejected heat, the third of QC, QH and W.

It then compares the claim with the model’s reversible ceiling: Carnot efficiency or Carnot COP, the finite-stream limit with Sgen = 0, the Betz limit, ρgQH, the Petela–Landsberg radiation limit or −ΔG × rate.

03

Interpret the feasibility verdict

  • FEASIBLE The balances close and the claim is within the reversible limit.
  • NOT FEASIBLE A balance fails, Sgen < 0, a temperature cross, or the limit is exceeded.
  • INSUFFICIENT DATA A required value is missing; the report names it.
  • MODEL REQUIRED No validated model exists here for this process.

Feasible means thermodynamically allowed — not efficient, economic or practical.
